# BGMの音程と端末音声回路

BGMとSEは `acquireGameAudioContext` で取得する単一の端末クロックを使う。端末が選んだサンプルレートを維持し、音源の44.1kHz／48kHzは同じ回路へリサンプリングする。音楽は専用Gainから直接出力し、SEの音量・リミッターを通さない。

Tone 15.1.22はパッケージ入口の評価時に既定Contextを作る。入口を読む前に `tone/build/esm/core/Global.js` から共有回路を設定し、余分な端末Contextの生成を防ぐ。この内部パスを変更する依存更新では `e2e/bgm-pitch.spec.ts` の生成数・周波数チェックを維持する。

BGMは等速・音程維持を設定する。iOSのMediaElementSource経由では自動loopでリサンプラーがEOFに残るため、同じ解放済み要素のendedで先頭へ戻して再生する。要素を替えて自動再生許可を失うことを避ける。復帰処理は待ち続けるresumeをロックせず、再試行できる。端末が回路を閉じた場合、HTMLAudioElementを新規に接続する（同じ要素へ2個目のMediaElementSourceは作れない）。曲・位置・音量・一時減衰を引き継ぎ、古い要素のmetadataイベントは無視する。BGMの破棄はSEが使う回路を閉じない。

検証音源はHTTP Rangeに対応させる。WebKitは速度変更・途中位置の再開で範囲読み込みを使い、単純な200応答だけのモックでは再生失敗を誤検知する。375Hzを44.1kHz／48kHzで配信し、実際のBGM出力の周波数・ループ・復帰・独立音量をChromium／WebKitで確認する。これらはiPhone実機の不定期な端末症状そのものの再現を保証しない。

音源ファイル・波形・曲の選択・保存形式は変更しない。
