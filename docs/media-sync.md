# 動画の同期検査

攻略日記 part1.1 で、短い校正動画とブラウザ再生の成功を、完成した長尺動画の同期確認と取り違えた。これは再生可否の検査であり、音ズレがない証拠ではない。公開時のゲートを分ける。

1. 録画中の開始・途中・終了に、同じ瞬間の映像／音の基準を記録する。ゲームの外に検査用の帯を置き、映像は公開前に切り落とす。検査用の音も除去する。
2. 録画の時刻基準を測定し、必要な補正を行う。単一の録画コンテナであっても、無音・パケットの時刻・クロックの違いを確認する。
3. 編集するカットは、映像と音を同じ入力・範囲・倍率で処理する。中間は48kHz PCMと30fpsのMOVを使い、1フレーム=1600サンプルで長さを揃える。AACへの変換は最後に1回だけ行う。
4. キャッシュのキーには録画・図・範囲・倍率・処理コードのハッシュを含める。既存ファイルがあるという理由だけでは再利用しない。
5. 公開する完成動画の中で、戦闘の序盤・中盤・終盤を含む複数箇所の実画像と効果音波形を元のカットへ照合する。長さだけの検査や校正動画のみで代用しない。ナレーションも元の音声と照合する。
6. 映像・ゲーム音・ナレーションの誤差上限は80ms。相関が低く判断できない点は合格に数えない。必要数が不足すれば止める。完成ファイルのSHA-256を報告へ入れ、書き換わったら再検査する。
7. デコード全編検査、Chromium/WebKit再生・シークは別ゲートとして維持する。これらのみでは同期を合格にしない。

今回の制作入口は `artifacts/tower-diary-1-1/sync-v3/`。元の攻略記録・ゲームの数値・ナレーション内容を変更せず、媒体の録画／編集を交換する。

回帰試験:

```sh
OPENBLAS_NUM_THREADS=1 python tools/media-sync/test_media_sync.py
```

300msの正負のズレ、時間経過によるクロックのズレ、逆行した基準、検査音の除去、フレームとサンプル数の一致を検査する。再生可能な不良ファイルも不合格になることが重要。

最終ミックスでは、映像に対応するゲーム音の全リールとナレーション・BGMを、48kHzの同じサンプル0へ揃えたWAVへまとめる。`tools/media-sync/build_soundtrack.py`を使う。元素材が合っていても最終音声トラックだけ遅れた再書き出し候補（約445ms）は、完成ファイルの波形検査が不合格にした。配布するファイルは、この不合格候補とは別に検査する。

ゲーム音がない更新解説等は、ゲーム音の検査点を捏造せず、含まれるナレーションを元の音源へ照合する。ゲーム音がある攻略日記では、完成ファイルの実ゲーム音照合を省略しない。
