# 戦闘の状態変化フィードバック

既存の常設状態アイコンとタップ詳細は維持し、状態変化の結果を対象の近くに短く表示する。新しい操作や戦闘補正、保存フィールド、常設の説明欄は追加しない。

- `platform/status-feedback.ts` は演出直前と記録済み `unitsAfter` を比較する純粋な変換。攻撃上昇、防御低下、継続回復、障壁、状態耐性、防御、かばうの付与・更新と、4状態異常の付与・解除を扱う。
- 抵抗、行動不能、同士討ちは `statusAction` を使用。抵抗を付与成功に見せない。戦闘不能時の状態消去は「解除」と呼ばない。
- 障壁の被弾は攻撃系イベントかつ実際の対象かつ記録された吸収がある場合のみ、対象ごとの障壁減少量を表示。HPが減らなければ `RESIST`、一部吸収なら吸収量、使い切れば消失。障壁破壊スキルは破壊と表示する。
- 消費・修繕・期限切れ・ボス自身の障壁解除を吸収や抵抗と誤認しない。状態耐性による抵抗と障壁によるHPダメージ全吸収は別のラベルにする。
- `StatusFeedback` は既存のHP着弾スナップショットを待つ。ルネットの多段必殺は途中スナップショットで最終状態を先出ししない。演出速度を変えても同じイベントを重複表示しない。
- 味方は顔グラ近く、表示中の敵は立ち絵の近く、表示していない敵は名前付きで表示する。全体付与などで重なる通知は上下にずらす。
- 月・電撃・霧・ハート等の共通アイコンと短い波紋を使い、既存状態アイコンを一度だけ強調する。同士討ちは本人から実際の対象へ短い軌跡を出す。
- 1.5秒の有限演出のみで、常駐の描画ループ・新しい音声処理は追加しない。動きを控える設定では文字だけ残し、波紋・アイコンの動き・軌跡を止める。

検証: `tests/status-feedback.test.ts`、既存HP差分・状態異常テスト、`e2e/status-feedback.spec.ts`、既存加速UI・操作音所有権・状態異常テスト。
