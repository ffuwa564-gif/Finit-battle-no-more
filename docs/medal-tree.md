図鑑 → 勲章。31種類・4系統から57種類・6系統へ拡張する。分岐全体の輪郭を表示し、既得・挑戦可能・未解放を区別する。獲得条件を確認して目標設定し、勲章名を称号にできる。戦闘能力や通貨報酬は付けない。

## 「壊れた彼女」

IDは `broken-girl`。第2章の会話 `c2-after`「今日は眠っています」を最後まで読み終えることが条件。前提は「朝の庭で」→「もうひとつの茶碗」。フレーバーは「私を忘れても。明日も、お茶を持っていく。」。未取得時は名称・本文・フレーバーを伏せ、既得になってから表示する。会話を途中で閉じた場合や、ダンジョンだけを踏破した場合は授与しない。

古いセーブで第1・2章が「引き継ぎ済み」になっている場合は、勲章詳細から対応する会話を読み返せる。引き継ぎだけでは読了を捏造しない。最終台詞の確認後に勲章の証跡だけを保存し、現在の章・移動・選択・会話完了フラグは書き換えない。選択肢のある過去の会話でも、今回選んだ回答を現在の物語へ書き戻さない。途中保存と再開、途中で閉じる操作に対応する。

## 表示

- 全体・系統別の取得数と進捗、最近の勲章、追跡目標を表示する。
- ランク0〜1は銅章、2〜3は銀章、4〜5は金章、6以上は冠章。表示上の格付けであり能力補正ではない。
- 未解放の遠い枝も形を表示し、ノードの位置は開放前後で動かさない。
- 前提を飛び越す接続線は外側を通し、無関係の勲章を通過させない。同じ段の3ノードにも対応し、重複する定義座標は検証で拒否する。
- 条件を満たしたが前提待ちの勲章は、既知の詳細画面にその状態を表示する。
- 未取得の秘密勲章が残っている場合に「すべて獲得」と表示しない。
- 新たな常時アニメーションや戦闘中の説明テキストは追加しない。

## 判定と保存

定義は `src/content/medals.json`、判定・保存契約は `src/domain/medals.ts`。`check:content` で前提、参照先、座標、実績の到達可能な上限を検査する。共通Button・Modal・NovelStageを使用する。

`MedalState.proofs` は一度観測した進捗の最大値。前提勲章が未取得の間にも記録し、その後石を分解したり設備を使い終えても達成記録を失わない。昔のセーブに残っていない出来事は推測しない。既得勲章・称号・目標のIDを保持し、証跡のない1.25の状態も受け入れる。1.25以前の移行は戦闘途中・旅程・会話・乱数を維持する。

記憶石は確定済み・研磨済みの所持品だけを評価する。装備中の石は所持品リスト内の1個として数え、二重計上しない。原石の内部結果・未採用の調律候補は含めない。T6は威力または特性値がT6である石。術式違いの数では変種違いを別種類に数えない。研磨・製作・調律確定の実コマンド直後に判定する。

判定1回ごとに遅延集計を共有し、工房の製作集計・塔・章などを各ノードで繰り返さない。観測済みの満額証跡や既得勲章は不要な再集計を省く。判定は乱数を消費しない。

## 戦闘の証跡

固有の戦闘条件は新しい探索から観測する。生成イベントを1回だけ検査し、演出の再生では数えない。報酬の獲得確定時だけ永続化し、全滅・撤退では固有戦績を確定しない。過去のスキル使用が保存されていない旧探索に、途中から証跡を捏造しない。

狼のボス撃破と生還、エレインの瀕死からの回復、リオラのかばうと全員生還、ノエルの2体同時撃破、セリスの貫通決着など、既存の判定は維持する。全12種の一覧は「戦術の引き出し」「十二の答え」の詳細で確認できる。

## 検証

- `npm test -- --maxWorkers=2`：全単体テスト。
- `npm run build`：型・コンテンツ・共通UI・翻訳と製品ビルド。
- `npx playwright test e2e/medals.spec.ts e2e/medal-progression.spec.ts --workers=1`：目標・称号の保存、実際の獲得、過去会話の読了、途中終了、記憶石への移動、秘密の保持、日英320/390/1440pxの表示・重なり・誤接続・文字切れ。

## 今回の確認結果

- mainのBGM共通クロック修正を取り込んだ状態で、111ファイル・892件の単体テストが成功。
- 製品ビルド、型・コンテンツ・UI契約・翻訳チェックが成功。
- 新規3シナリオをChromiumとWebKitで確認。日英320/390/1440pxの全系統表示、接続線が別ノードを通らないこと、過去会話の読了と途中終了、称号の再開、実際の石一覧への移動、未完了の秘密勲章があるときの表示を含む。
- WebKitはLinuxの実ブラウザで検証した。実機iPhoneの検証ではない。検証環境に不足するliblzo2/libGLESv2を一時ディレクトリへ用意し、LD_LIBRARY_PATHで参照した。ldconfigだけを見るホスト検出は一時パスを認識しないため、その事前検出のみを除外して実際のブラウザを起動・操作している。ゲーム・テストのアサーションは省略していない。通常のCIではPlaywrightのブラウザ依存パッケージを導入する。
- 初回の全体実行で既存の重いテストが5秒制限に達した。勲章の集計を共有する形へ修正し、制限時間を引き上げずに全件を通した。
