# XRと星晶の祈願

SSRの上位レアリティとしてXRを追加した。今回はレアリティ・専用通貨・解禁判定・抽選・表示の仕組みを先に実装し、実際のXRキャラクターと星晶石の入手先は後で追加する。現段階ではXRは入手できない。

## 現在の公開状態

- 専用通貨は「星晶石」。通常の祈願石・ゴールド・素材とは別に保存する。
- 新規セーブは星晶石0個。報酬・ドロップ・ショップ・交換・配布・通常石からの変換は追加していない。
- 本編は現在3章まで。第10章が存在しないため、現在の全ダンジョンをクリアしても解禁されない。
- ガチャ画面に「星晶の祈願」の準備中表示、星晶石残高、将来の解禁条件を表示する。抽選ボタンは無効。
- ガチャ設定は `published: false`。XRキャラクターの登録もまだないため、開発用に石だけを増やしても引けない。
- XRは通常ガチャ、既存のSSR保証、イベント交換、ゴールド交換へ混入しない。

## 強さと表示

キャラクターのレアリティはR／SR／SSR／XR。素材のcommon／rare／epicとは別の分類。

XRの強さは31〜40（画面上は3.1〜4.0）、既存レアリティは10〜30を維持する。同じ役割・条件ならSSR上限より高い基礎HP・攻撃・防御になる。速度など、強さで上がらない既存の役割特性は変えない。スキルの強さも40まで扱えるが、各キャラのスキル予算・強さ帯の検査は継続する。

XRは白金・氷色・薄紫の専用枠とバッジ、獲得表示に対応する。実際の人物・原画・動画は後日のコンテンツ追加とする。

## 将来の解禁条件

`xrChapterCleared` は第1章から第10章までが連続して定義され、各章の全ステージが公開されており、全てが報酬確定後の `completedDungeonIds` に含まれることを要求する。ステージの総クリア数や、第10章の最終ボスIDだけでは解禁しない。探索中の仮クリアも対象にしない。

実際に引くには、さらにガチャ公開フラグ、有効な排出候補、星晶石残高、探索外であることを確認する。UIの無効化だけでなく、`applyCommand` の `drawXR` でも検証する。第10章のシナリオやステージそのものは今回追加していない。

## 暫定の抽選仕様

排出率は今後の調整用の仮設定。`src/content/xr-gacha.ts` に集約する。

| レアリティ | 基準排出率 |
| --- | ---: |
| R | 70% |
| SR | 25% |
| SSR | 4.9% |
| XR | 0.1% |

単発は星晶石1個、10連は10個を開始時に必要とする。抽選は保存済み乱数から順番に行い、10連は単発10回と同じ結果・残高になり、保存は1回で確定する。

通常ガチャの2回目SSR保証・90回天井・74回目からのSSR確率上昇は持ち込まない。XRの天井や初回保証は未設定。通常の祈願回数・SSR天井・通常石残高はXR抽選で変わらない。各レアリティ内は均等抽選。

重複時の暫定還元はR／SR／SSRが0、XRが星晶石1個。通常石で還元しない。将来公開する前に排出率・候補・還元・天井を確認する。公開時は正の確率を持つ全レアリティに有効なキャラクターが必要。

## セーブ互換性

`astralStones` と `xrDrawCount` は省略可能な非負安全整数。旧セーブの未設定値は0として扱い、保存形式の版や既存の所持キャラ・探索・通常ガチャの天井は変更しない。バックアップにもそのまま含まれる。不正な小数・負数・非有限値は拒否する。

XR抽選の結果には `currency: 'astralStones'` を記録し、通常抽選の結果とは還元通貨と回数を分離する。結果一覧内で通貨が混在するデータは拒否する。抽選に失敗した場合は入力セーブを変更せず、石も消費しない。

## 将来公開するときの手順

1. 第4〜10章の正式ステージを追加し、解禁条件を実際の進行で確認する。
2. XRの人物・原画・スキルを追加する。XRの入手経路は `xr_gacha` 専用とし、通常の排出一覧には入れない。
3. XR候補を専用ガチャへ登録し、暫定の確率・還元・天井を決める。
4. 星晶石の入手経路を別途実装・検証する。今回の段階では作らない。
5. ガチャの `published` を有効にし、実際の章進行・専用通貨・単発・10連・重複・再起動・表示を確認する。

テストでは架空の追加章とXRキャラを使って将来の抽選経路を検証する。これらのテスト用コンテンツを製品データへ追加しない。
