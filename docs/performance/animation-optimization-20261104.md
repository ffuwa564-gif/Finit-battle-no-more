# アニメーションを残す描画最適化（2026-11-04）

目的は、元の顔グラ動画と庭のアニメ素材を残して、背景描画の不要な仕事を減らすこと。公開版への導入・実機での温度改善はまだ認定しない。

## 変更

- 発生していない／終了した背景イベントのシェーダー計算をスキップ。透明な粒子のフラグメント計算も早期終了する。
- 背景のゆっくりした動きは15fps。戦闘イベントが来ると次の描画機会から30fpsに戻し、最長の粒子寿命を覆う2.8秒間維持する。
- 描画間隔の端数を保持し、画面のリフレッシュ周期による更新頻度の低下を防ぐ。イベント発生時刻を渡し、低頻度の背景時計に攻撃演出を合わせない。
- 既存の共通アニメーション停止状態に背景WebGLを接続。停止・復帰でコンテキストを作り直さない。下地の粒子・粒状感も休ませ、前面の物語演出は動かす。

顔グラ640×960の動画、枠720×960のWebP、結晶512×512のWebPは元のファイル・品質・再生指定を維持した。描画解像度の上限も変更していない。戦闘エンジン、セーブ形式、音声、操作パネルのレイアウトは変更していない。

## 検証

- `npm run build`：成功（型、コンテンツ、共通UI、翻訳チェックを含む）。既存の大きなチャンク警告は残る。
- Vitest `ultimate-effects` / `ultimates` / `portrait-framing`：29件成功。
- 既存 `e2e/effects.spec.ts`：3件成功。WebGLの全演出、セーブ非変更、コンテキスト喪失、OS設定、静止フォールバックを検証。
- 新規 `e2e/scene-optimization.spec.ts`：2件成功。背景15fps・戦闘30fpsへの復帰、描画停止、前面の粒状感継続、同じWebGLプログラムの再利用を検証。
- 同テストは公開版 `96d2e00` の独立したレンダラーを参照し、待機・9種類の演出と寿命切れ・1時間後の時計補正・フレーム間の発生時刻の計21条件を比較する。許容差は8bitチャンネル最大2、平均0.01未満。全条件が範囲内。
- 既存の高解像度顔グラの最初のretinaケース：成功。
- `e2e/acceleration.spec.ts` の戦闘表示ケース：単独再実行で成功。最初の並行実行は30秒の待機でタイムアウトしたため、初回成功とは記録しない。
- 新規2件は最後の `SceneAtmosphere` 前面／下地の区別を加えた後にも再実行して成功した。

## 負荷測定の範囲

`animation-optimization-20261104-results.json` に全6サンプルと環境情報を保存する。基準は公開版ソース `96d2e00899b6bcbff31f47433a59d4aec8268988`。変更後ソースのハッシュと差分は同じディレクトリのprovenanceに記録する。

同一マシン・Chromium・390×844・DPR3で、忘却の聖堂（`silent-cathedral`）の戦闘待機状態を使用。合法なエンジン生成状態、シード42、アテナ／ノクス／覚醒ルネット／覚醒セリス、音量0、動き軽減なし。7秒ウォームアップ後8秒測定、変更前後各3回、順序を交互にする。毎回4本のHQ動画が実際に再生中であること、元の枠・結晶ファイル、WebGLとページ可視状態を確認する。

ここで測れるのは **Linux Chromium + SwiftShaderによるソフトウェア描画のブラウザプロセスCPU時間**。CPU割当は4コア分、100%は1コア分。物理GPU、iPhone/Safariの温度・電力・連続戦闘の負荷は測定していない。飽和状態のため、CPU比だけで実機での効果を推定しない。描画呼び出し数は完了フレームや表示fpsの保証でもない。8秒・各3回という短い測定の中央値を、統計的に確立した削減率とは扱わない。

静止画像の目視ではレイアウト・顔グラの品質が保たれていることを確認した。画像間の動画・枠の位相は同期しておらず、スクリーンショット全体を一致画像とは扱わない。動きの滑らかさは実機で別途確認が必要。

## 測定結果

| 戦闘待機画面 | CPU中央値（1コア=100%） | 3回の範囲 | 描画呼び出し/秒の中央値 |
| --- | ---: | ---: | ---: |
| 変更前 | 389.73% | 375.12–399.04% | 13.72 |
| 変更後 | 369.36% | 368.83–397.31% | 11.65 |

中央値の差は約5.23%低下。ただし範囲は重なり、3組目は変更後の方が重い（389.73→397.31%）。**一貫した改善や実機の発熱対策の完了を示す結果ではない。** ソフトウェア描画で飽和し、目標15/30fpsを達成したという測定でもない。待機画面の小幅な削減候補として、実機確認用のdraftに留める。操作中の攻撃、セーブ、音声、連続戦闘の消費をこの数字に含めて解釈しない。

## 再現

1. 同じリポジトリの別worktreeで `96d2e00` をチェックアウトし、`npm ci && npm run build`。
2. このブランチでも `npm ci && npm run build`。
3. 他のビルド・ブラウザ試験を止め、`npx tsx scripts/performance/animation-optimization.mts /absolute/path/to/baseline-worktree`。
4. `artifacts/animation-optimization/` のraw/report JSON、測定差分、スクリーンショットを確認する。PlaywrightのChromiumが必要。

比較スクリプトは先の `investigate/battle-load-20261104-165464` 調査を基にしている。背景15/30fps・早期終了・非表示時停止をまとめた試作の比較であり、それぞれの寄与を分離した測定ではない。元のWebPや動画のデコード負荷は残る。さらに改善する場合は、枠の光を独立した小さな描画へ分けるなど、素材の再設計を次の別課題として評価する。
