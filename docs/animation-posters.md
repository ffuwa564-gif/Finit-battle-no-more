# アニメーションと静止画の構図をそろえる

ルネットで、2:3の生成原画を3:4の全身動画と別切り抜きの顔枠動画の両方へ流用し、静止画への切り替え時に表示倍率が変わる問題があった。以降は動画ごとの表示静止画を必須にする。

## 制作・登録の手順

1. 元絵は制作資料として保持し、配信用動画を完成させる。全身用・顔枠用の切り抜き、寸法、フレームレートを先に確定する。
2. `src/content/index.ts` に動画を登録し、実ファイルと同じ寸法を書く。`withMotionPosters` が各動画に専用の `posterId` と静止画アセットを追加する。全身版と顔枠版は別の動画として扱い、静止画も別々に作る。
3. `npm run export:motion-posters` を実行する。全17本を含む登録済み動画の先頭フレームを、`public/art/motion-posters/<動画ID>.png` へ無拡大・無切り抜き・RGBのPNGとして書き出す。FFmpegとffprobeは固定バージョンのnpm開発依存（`@ffmpeg-installer/ffmpeg`、`@ffprobe-installer/ffprobe`）から絶対パスで起動する。`npm ci` で実行環境に合うバイナリを準備するため、CloudflareのようにシステムのPATHへFFmpegを追加できない環境でも同じコマンドを使える。
4. 動画と生成されたPNGを一緒にコミットし、`npm run build` を実行する。動画を差し替えたり切り抜きを変えたりしたら、必ず静止画も再書き出しする。

元絵に対して倍率を手調整して似せる方法は使わない。表示静止画を個別に加工すると、後述の検査に失敗する。生成原画を編集したい場合は、制作資料側を編集し、動画の確定後に表示静止画を再生成する。

## 実行時の仕組み

`AnimatedIllustration` は動画アセットの `posterId` を使い、呼び出し元から渡された別構図の元絵より優先する。動画ロード前・HTML videoのposter・動き軽減・通信量節約・再生エラーで同じ静止画を表示する。顔枠は顔枠動画に対応する静止画を使うため、全身用の絵を拡大して代用しない。

詳細画面の表示枠の縦横比も、動画がある場合は動画の寸法を基準にする。画像と動画の位置・object-fit・変形が一致することはブラウザーテストで確認する。非アニメーションキャラクターの原画表示は従来どおり。

## ビルドで止める条件

`npm run check:content`（通常ビルド・itchビルド・公開用ビルドから実行）で以下を検査する。

- 各動画に有効なPNG静止画アセットがあること。
- 登録上の動画・静止画の寸法が一致すること。
- ffprobeで読んだ実寸も登録値と一致すること。
- 動画の最初の1フレームと静止画をRGBでデコードし、画素内容が完全一致すること。同じサイズの別構図や、動画差し替え後の古い静止画も検出する。

チェック時に素材を自動修復しない。不一致があれば失敗し、明示的に書き出し直す。FFmpeg/ffprobeがなければ検査を省略せず失敗する。GitHub Actionsの検証・itchビルド・Cloudflareビルドもnpm依存のバイナリで同じ検査を実行する。システム側のFFmpegやaptへの依存はない。npmのoptional依存は省略しないこと。

## テストの役割

`tests/motion-posters.test.ts` は参照漏れ、不一致寸法、同じサイズの別画像、実ファイルだけ違う寸法を意図的に作って検出を確認する。PATHを空にした状態でも実動画とPNGの書き出し・検査が通ることを確認し、Cloudflareでの実行ファイル不足の再発を防ぐ。`e2e/motion-posters.spec.ts` は全アニメーションキャラの全身・顔枠と既定ホームで、動画・静止画の寸法と画面上の配置が一致することを確認する。

この対策の対象は静止画と動画の構図のずれ。動画の途中の形崩れやループ境界の自然さは、連続再生による確認を別途行う。視聴承認を自動で記録するものではない。
