# 実装・動作確認・公開手順

初期実装はReact＋TypeScript＋Viteの静的Webアプリです。ゲーム状態はブラウザーのIndexedDBに保存し、配信先はCloudflare Pagesを想定しています。アカウント接続、Cloudflareプロジェクト作成、DNS設定、実デプロイは行っていません。これらはユーザーが行います。

## 開発

```sh
npm ci
npm run dev
```

Viteの表示URLをブラウザーで開きます。画面のURLはhashで切り替え、サーバー側の画面ルーティングを必要としません。同一オリジンの同じブラウザープロファイルで再開してください。プレビューURL、本番URL、独自ドメインではセーブ領域が異なります。

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

`build` は開発確認用です。型、全コンテンツ定義と実アセット、共通UIの使用経路を検査してから `dist/` を作り、実装と出力ファイルのハッシュを接続するビルド記録を残します。公開承認が済んだことは意味しません。公開包装はその後にソースや出力が変わっていれば拒否します。

## コンテンツとUIの追加

1. `src/content` の単一台帳へ追加します。既存効果で表現できる追加に、キャラ固有の戦闘コードや画面別の登録配列を作りません。
2. 画像は `public/art` に置き、台帳にアセットID、パス、種別、寸法、アンカー、権利情報を登録します。
3. `npm run check:content` で全参照・役割・意味キー・素材・公開入手経路・ファイルを検証します。
4. `npm run check:ui` で、画面層の独自ボタン、ネイティブ要素への操作処理、内部UI・音声APIの直接使用、inline style等を検出します。共通部品は `src/ui` の公開窓口から使ってください。許可した例外はcomposition rootの音声イベント接続だけです。
5. 共通プレビューで追加した画像・文章・演出を確認します。静的チェックは顔の切り抜き、読みやすさ、音の適切さまで保証しません。共通部品を変更した場合は既存画面への影響も確認します。

## SEとBGM

SEはTone.jsのシンセサイザーで生成します。`src/platform/audio.ts` の共通イベント窓口に集約し、画面・キャラごとに別の再生処理を作りません。最初のユーザー操作後に音声を有効化し、SE音量0でミュートできます。ブラウザーが音声を拒否・中断してもゲーム結果には影響させません。

通常素材、レア素材、希少素材では異なる音列を再生します。レアな音は音量だけでなく音数・余韻で区別します。BGMは指定の甘茶の音楽工房からの正式な選曲・規約確認・権利記録が未完了のため、無断で同梱していません。BGM設定は採用ファイルの接続前には音を再生しません。

## 視聴確認と公開ゲート

```sh
npx tsx scripts/check-approvals.ts --report
```

`.reports/content-review.json` に、コンテンツ版と実装・画像等のファイルハッシュを出力します。この操作は承認を記録しません。共通プレビューと実際の画面を見て、各イベントの音を聞いた担当者が、確認後にルートの `content-approval.json` を記録します。

```json
{
  "contentVersion": "レポート内のcontentVersion",
  "fingerprint": "レポート内のfingerprint",
  "reviewer": "実際に確認した担当者名",
  "confirmedAt": "実際の確認日時のISO文字列",
  "visualConfirmed": true,
  "audioConfirmed": true
}
```

未確認のまま上記のフラグを真にしてはいけません。現行の初期ゲートは、版・全ファイルの集合をまとめて確認する保守的な方式です。差分IDごとの確認記録再利用は設計書の拡張要件であり、まだ実装していません。内容が変わると承認は失効します。承認のない初期状態では公開用コマンドが失敗するのが正しい動作です。

```sh
npm run release
```

テスト、開発ビルド、視聴承認がすべて成功した場合だけ、Cloudflare Pagesへ渡す `dist-release/` を生成します。コマンドはアップロードしません。`dist/` 単体を本番へ出すと、固定版再開用の起動ページが含まれないため、本番用の出力先には使いません。

## Cloudflareへの受け渡し

- ビルドコマンド：`npm run release`。
- 公開ディレクトリ：`dist-release`。
- 公開用の視聴確認記録をコミットしてから実行してください。初回の接続・配信設定はユーザー担当です。
- 初期構成ではWorkers、R2、D1、秘密鍵、APIトークンは不要です。
- 本番オリジンを固定してください。URLの変更はブラウザー保存先の変更です。
- `_headers` は起動ページ・配信一覧の再検証と、リリース配下のimmutableキャッシュを分離します。実際のCloudflare配信で適用状態を確認してください。

`dist-release/index.html` は安定した起動メタだけを読み、進行中の探索があれば同じオリジン内の `/releases/<appVersion>/` を選びます。保存メタと対応リリースが不一致なら、セーブを消さず停止します。各リリースにはindex、実行コード、画像、互換manifestを含めます。既存ディレクトリの内容を別物で上書きする場合は、同じ版を再利用せずappVersionを上げてください。

以前のリリースは、次の成果物の `dist-release/releases/` にも残す必要があります。ローカルで残っているディレクトリは包装時に維持・ハッシュ検証しますが、クリーンなCI環境には自動復元されません。過去の承認済み配布物をCI入力として復元してから包装してください。Cloudflareの過去デプロイURLを旧版アセットの保持先と見なさず、未確定探索がある利用者向けの旧ディレクトリを欠落させないでください。

初回は旧リリースが存在しません。二回目以降の公開では、同じ本番オリジンの旧index、manifest、主要画像・音が取得可能で、HTMLの誤応答ではなく期待した形式・内容・ハッシュであることをプレビュー配信で検証してください。URL変更、アップロード失敗、キャッシュ設定、古い版の削除までローカル包装だけで保証することはできません。

## 現段階の限界

- 合成SE以外のBGM、正式イラスト、配信確認、実機での音と見た目の最終承認は別途必要です。
- 初期リリース0.1.0／保存形式1以外のセーブ移行は未実装です。対応できない版を自動初期化しません。
- ローカルセーブの不正改変耐性、複数端末同期、サーバー抽選は提供しません。
- コンテンツの数値バランス・周回時間・素材獲得分布は、実プレイで確認する課題です。

## 参考画像に合わせた表示

ホームとバトルは共通UI配下のhome.cssとbattle.cssで構成し、画面からの外観上書きを避けています。メニューは3列×2段、バトルはステージ・顔グラ帯・操作面を一つの枠へまとめました。顔グラ専用のface variantは台帳のportraitZoom/portraitOriginでクロップを指定し、全身立ち絵や詳細表示を変更しません。小さい画面では内容を圧縮しすぎず縦スクロールを許可し、操作がナビに隠れないようにしています。

敵の遠近表示は共通EnemyCarouselへ集約しています。表示の回転はコンポーネント内の状態で、ゲームのコマンドやセーブを変更しません。外側の配置と内側のdata-unitアニメーションを分離し、撃破・素材ドロップ時にも必要な敵の位置を保持します。横スワイプと縦スクロールを区別し、左右ボタンとキーボードも使用できます。

メニュー用のmenu-hero、menu-bag、menu-codexと、通常敵6種の描画アセットは台帳参照で管理します。キャラクターの立ち絵が縦長かどうかを台帳寸法から判定し、単体表示時の拡大を共通クラスへ限定しています。個別キャラIDによるCSS分岐は追加していません。


## シェーダーとパーティクル

SceneEffectsはホーム原画と敵ステージへ透過Canvasを重ねます。fx-rendererはWebGL1のGLSLで月光・薄霧・微粒子を描き、GL_POINTSで攻撃、範囲魔法、回復、防御、強化、弱体、ドロップ、Wave切替、敗北の共通演出を描きます。レア素材は金、希少素材は淡い紫の星状粒子と光輪を使います。presentationの同じBattleEventがGSAP・生成SE・GPU演出へ進み、キャラごとの演出実装は不要です。表示乱数は戦闘の乱数とは独立し、結果・素材・再生速度・セーブを変更しません。

描画は最大30fps、DPR1.5、140万画素・各辺2048px、粒子176個・光輪5個を上限とします。非表示タブ・画面外では描画を停止し、画面退出時にGL資源とリスナーを解放します。ゲームの動き軽減設定とOSのprefers-reduced-motionを尊重し、WebGL非対応・初期化失敗・コンテキスト喪失時も静的な月光へ切り替えて操作を続けられます。Canvasは入力を受けず、顔グラ帯・大きな操作面・トーストの視認性を保ちます。外部シェーダー配信や追加ライブラリは不要です。

ブラウザー検証では実際のGLSL描画・全9演出のGLエラー、演出だけでは保存内容が変わらないこと、GPUコンテキスト喪失後の操作、OSの動き軽減切替、WebGL非対応時のメニュー操作を確認します。CIのGPU検証にはChromiumのSwiftShaderを使用します。物理端末ごとのGPU性能と発熱は別途実機で確認してください。


## 見本との追加調整

ホームと探索はデスクトップでも独立した縦型のゲーム枠を中央に配置します。ホームは共通TownNavigationを枠の下端へ埋め込み、街のほかの画面では同じ部品をモバイル用の固定ナビに使用します。アクティブな行き先とボタン処理も共通化し、別々の見た目や挙動を作りません。ホームの設定図案は彫金風の天球儀とし、紙の均等な横縞を抑え、薄い銀縁・淡い石紙の陰影・読みやすい日本語ラベルに揃えています。

戦闘の操作面は左に大きな円形の3作戦選択、右に大きなラウンド進行ボタンと回復薬・撤退を配置します。既存の作戦指示というルールに沿う実ボタンを使い、移動パッドや個別攻撃指示は追加しません。戦闘中の外側ヘッダーを省いて舞台を広げ、効果音の切替は操作面へ移しています。敵の遠近表示、顔グラ帯、共通シェーダーとパーティクルを維持します。


画面の説明文は、同じ操作の繰り返し案内・実装方式・版情報・飾りの定型文を省きます。必要な操作名、費用・排出率、編成数や踏破数、キャラクターのフレーバー、素材喪失と報酬確定の注意は簡潔に表示します。開発用の共通プレビューは直URLで確認でき、設定画面の通常導線には置きません。


見本への追加調整では、単体の縦長敵を上半身中心の構図へ寄せ、顔をHP帯の下に置きます。横長の生物と複数敵の遠近配置は共通カルーセルの従来の配置を使います。操作面は彩度・光沢を抑えた灰青の彫金表現に揃え、CommandEmblemで作戦・進行・薬瓶の図案を共通化します。図案の種別は型で限定し、分岐の網羅をコンパイル時に確認します。短い表示ラベルでも、操作ボタンのアクセシブル名は従来どおり維持します。ホームのリーダー顔・6図案・日本語ラベルを大きくし、下部ナビでも同じメニュー図案を再利用します。


作戦選択は共通StrategyDialへ集約し、外周の3つの実ボタンで作戦を指定します。中央は現在作戦の図案を表示する非操作のメダリオンで、移動や個別攻撃などの機能を追加しません。選択をaria-pressedと内側の縁で示し、44px以上の操作領域を確保します。パーティは画像内の名前と太めのHP帯を持つ一体のリボンへまとめ、敵HUDの余分な四角い枠を減らしています。ホームのタイルは外影と継ぎ目を抑えて同じ石紙へ統一し、探索入口の文字を中央へ寄せます。

PortraitArtはホームのリーダー顔とパーティの画像描画を共通化し、台帳のanchor・portraitZoom・portraitOriginを使用します。画面ごとの固定倍率を増やさず、リーダーを変更しても同じ顔の表示設定を引き継ぎます。


紙肌はローカルの手続き的SVGをCSSの背景として使い、明るいホーム面・タイル・操作面だけにごく薄く適用します。文字や顔画像の上に紙目を重ねず、外部配信や追加ライブラリは不要です。ホームと戦闘には共通game-frameの銀縁と影を使用します。進行円は390px画面で144px、320pxでは116pxへ切り替え、薬・撤退をその上に配置して、作戦盤と左右の主従が伝わる構図にしています。


虚ろの守り手は銀髪・角冠・鍵杖の意匠を維持し、顔と鎧の線が明瞭な黒喪服の透過原画へ更新しています。原画の実寸1024×1535を台帳で保持し、表示のための無条件リサイズは行いません。敵情報の上段を薄くし、ボスの紋章・祈願石・ゴールドには共通Sigilsの彫刻風図案を使用します。ホームのプロフィールと残高は、イラストの頭を隠さない幅で拡大しています。
