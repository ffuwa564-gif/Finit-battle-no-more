# 月の庭：戦闘フレームと花の収穫

2026-10-28。ユーザーの要望は「フレームそのものがひとつのゲーム」。細いSVGの飾りと丸いボタンの案は不採用とし、Runwayで原画を描き起こした小さな庭へ変更する。

## 庭のループ

1. ラウンドを終えると下辺の結晶がひとつ育つ。
2. 各ラウンドの開花率は40%。抽選に外れても成長は残り、3回目には必ず開花する。
3. 下隅の花床に咲いた花を直接タップして収穫。3つの灯が消え、蕾へ戻る。
4. 次の戦闘でまた育つ。花を摘むかどうかは任意。

抽選は1つのWave・ラウンドにつき1回。花は1輪まで。最初のWave紹介だけでは開花しない。生きている味方に負傷者がいれば白花／青花を抽選し、全員満タンなら青花。次のATTACKで摘まなかった花は消える。Wave切替では庭もリセットする。時間制限による取り逃しは作らない。

- 白花：HP割合が最も低い生存味方を最大HPの18%回復。復活なし。全員満タンでは消費しない。
- 青花：HPが最も低い生存敵へ攻撃。生存味方の平均基礎攻撃力の150%を通常ダメージ計算へ渡す。かばう・障壁・防御を適用。特定の先頭キャラの攻撃バフは引き継がない。
- 撃破時は通常と同じ処理でゴールド・仮素材・確定素材・イベントの核・図鑑を処理する。腕試しは報酬なし。
- 収穫だけではラウンド、スキルの再使用待ち、ボスの予告／終鐘、薬の使用済み状態を進めたり戻したりしない。

`battle.blooms` は省略可能な保存情報。開花状態・成長・抽選ストリーム・最後に抽選した位置を保持し、再読込やバックアップ復元で抽選をやり直さない。UIのタイマーやマウントでは抽選しない。通常の戦闘・希少遭遇・ドロップとは別の乱数列を使用し、収穫による実際の撃破以外は既存の乱数進行を変えない。同じ花の二重使用はコマンド側で拒否する。旧セーブは花情報なしで再開可能。

## 原画と動き

フレームの素材は銀の根・深い青緑の蔦・月長石・白い蕾。下隅に2つの花床、下辺中央に3つの結晶。中央は透過し、顔や立ち絵を覆わない。敵名・HP・大技カウントは枠より前に描画。敵送りとボス状態表示は花床と成長表示を避ける。

原画はRunwayで生成。透明化を行い、細部の透過を追加の画像モデルで調整してからWebPへリサイズ。フレームの動画を常時再生する方式ではなく、ゲーム中のイベントと保存された庭の状態から、光の流れ・収穫・成長・花の動きを制御する。

- 味方攻撃：根を光が駆け上がる。
- 敵攻撃：枠だけが短く震え、結晶が薄紅に光る。
- 回復：白い花床に柔らかな光。
- 障壁／Wave移行：結晶の光が流れる。
- 必殺技：枠と両方の花床が強く反応。
- 収穫：実際の花の原画が光とともに散り、蕾へ戻る。

OS・ゲーム内の動き軽減では追加アニメーションを停止する。成長表示・タップ・効果は使える。花のタップ範囲は48px以上。白花／青花は色だけでなく形・短い表示・読み上げラベルでも区別する。音は承認済みの通常攻撃／柔らかい回復音を使い、ボタン音を重ねない。
