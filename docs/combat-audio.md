# 通常戦闘音の材質とキャラの個性

## 音作りの好み・継続方針（2026-10-26）

- ユーザーは通常攻撃用の雷パッチを好評価。現在の通常攻撃・攻撃スキルはこの雷を使う。
- **金属感が強すぎる音は避ける。** 金属の鳴りや鋭いベルを足すだけで豪華さを作ろうとしない。必要な場面でも控えめに使い、響きの長さ・高域の強さを確認する。
- 「祈り」はガチャの祈願ではなく、戦闘中の回復・祈りスキルを指すと本人に確認済み。回復音は柔らかく温かい音色を優先し、FMベルの硬い打ち出しや高い金属的な倍音を抑える。
- 好評の攻撃の雷と必殺技は、回復音の修正に巻き込まない。音の好みは自動検査では判定せず、試聴を踏まえて更新する。

## 金属的な補助音の調整（2026-10-28）

### 障壁・かばうの再調整

追加の指摘を受け、単に高域を抑える方式から音源そのものを変更した。前回の通常障壁には共通の胴鳴りと音程のある成分が、防御系必殺技には220／437／682Hzの共鳴が残っていた。現在は`protection-audio.ts`で、発振器・ベル・非調和倍音を使わない、帯域を整えたノイズの風・布のような保護音を生成する。

通常のguard／barrier全3テイクに加え、スキルIDを持たないguardイベントと防御系必殺技（ultimate-guard）も同じ方向に統一。通常ピーク上限はguard0.34／barrier0.28、防御系必殺技は0.60。必殺技の尺と接触タイミングを維持し、攻撃の雷・それ以外の必殺技・回復専用サイン波・BGMには変更を加えない。以下の「前回調整」の音程を含む保護音は、この方式に置き換える。

保護音の検査では、3サンプルレートで有限性・端点・可聴レベルを確認し、以前の主要な周波数へエネルギーが集中しないことを確認する。これは音程成分の退行を防ぐ検査で、聴感の好みを保証するものではない。

### 前回調整

ユーザーの「金属音が強い効果音を直す」という要望に合わせ、実際に再生される盾・結界のPCMと、強化・弱体・状態異常などの補助音を変更した。通常攻撃に割り当てる雷・必殺技・柔らかい回復用サイン波・BGMの音源と割当は維持する。

- 盾は鉄の非調和な共鳴を木の打音・柔らかな守りへ、結界は高い結晶音を低い音色・空気の膨らみへ置換。盾は1500Hz、結界は1800Hzの2段ローパスを通し、立ち上がりを9msに丸める。小さな反射音を0.04へ抑え、出力目標は盾0.58、結界0.50とする。最後の端点処理はフィルター後に行い、先頭・末尾を無音に保つ。
- 補助のFMベルを、2200Hzのローパスを通る三角波へ変更。18msの立ち上がり、180msのリリース、−8dBで、旋律を5半音下げる。反復エコーと金属打音用MetalSynthを外す。6声の固定プールとSE共通音量を使い、回復専用6声には影響させない。
- 自動検査は3サンプルレート・全3テイクの有限性、出力、端点と高域成分の上限、およびブラウザーの実出力で盾・結界・強化・解除が鳴ることを確認する。高域成分の数値は好みの点数ではない。

`npm run preview:combat-audio`で更新後の盾・結界3テイクを試聴できる。実際の補助シンセはブラウザーで確認する。以下の過去の音作り・数値は当時の記録であり、本節の対象ではこちらを優先する。

## 剣・雷・機巧射撃（今回の改善）

`combat-signatures.ts` の3つの音は、共通の胴鳴りを重ねる方式から独立して作る。剣は鋭い切断と非調和な鋼の共鳴、雷は瞬間の亀裂と不規則な小放電、機巧射撃は単発の圧と短い機構の反動。全体を同じtanhで潰さず、必要な胴の成分だけを飽和させる。命中は現在の画面と同じイベント開始に置き、存在しない振りのために戦闘を遅らせない。複数の小放電や反動は余波であり、追加ダメージやヒット数ではない。

ユーザーの試聴評価を受け、現在はキャラ・武器にかかわらず、通常攻撃と攻撃スキル（attack／area／pierce／shatter／drain／dawn）をthunderへ統一する。敵・味方・ビット射撃も同じ窓口を使う。paralysisもthunder。雷パッチ自体は試聴した版から変えず、同じ雷の3テイクをキャラごとに切り替える。blade／mechanismは比較用パッチとして残るが、通常プレイでの自動割当は行わない。必殺技は専用の既存音を維持する。

回復（heal／regen／mend_pair／barrier_mend／cleanse）はPCM素材の切替を止め、通常戦闘音補強前（711d103）の音列と和音へ戻した上で、現在は旋律を1オクターブ下げたサイン波の専用音源で鳴らす。回復薬・スキル・吸命後の回復・継続回復・リーダー回復にも適用する。HP吸収の攻撃部分は雷、その後の回復イベントは回復音。回復の音量・効果の戻りも共通SE音量を通る。専用音源は55msで柔らかく立ち上がり、1800Hzのローパスを通し、硬いFMベルと短い反復エコーを使わない。浄化の高域ノイズも回復系では省く。専用6声を固定で再利用し、480msのリリースが終わる前に再発音しない。元の和音の下支えと控えめな残響は残す。

各音色に3テイク。テイク間では材質と尺を固定し、接触の細部・共鳴の減衰・小さな余波の時刻を変える。剣580ms、雷680ms、射撃460ms、素材ピークはそれぞれ最大0.68／0.72／0.69。同じキャラが剣・鈍器・爆発を順に鳴らす方式にはしない。好評の必殺技のパッチとタイミングは維持する。

新たな通常音の接触時、再生中の通常音だけを4msで0.63（約−4dB）へ下げ、130msで戻す。既存automationを保持して連打時のジャンプを避ける。新しい音自体、必殺技、BGM、設定音量には適用しない。BGMのポンピングを避けるため、音楽のduckingは今回導入しない。通常PCMキャッシュ上限は既存27＋新規9＝36、独立カウンターは64、同時再生上限6を維持する。

`npm run preview:combat-audio` の先頭3行と `signatures-comparison.wav` で剣→雷→射撃を比較できる。単体素材なのでBGMと最終出力処理は含まない。試聴の好みは自動テストでは保証しない。

## 既存の9系統


通常戦闘の9系統は、各3種類、計27パッチを持つ。以前の音程約3%の違いから、発音源・材質・破片のリズム・共鳴・減衰の異なる構成に変更した。`combat-audio.ts` の `combatTakes` が名前と材質、尺、基音、重量成分を管理する。

| 系統 | バリエーション |
| --- | --- |
| attack | 一閃／重打／破裂 |
| pierce | 鋼の刺突／放電する貫通／装甲への刺突 |
| shatter | 砕裂／岩砕き／結晶破砕 |
| area | 爆発／重なる衝撃波／奔流 |
| drain | 吸引／脈動／侵食 |
| dawn | 光の炸裂／光線／陽光の波 |
| heal | 鐘の癒し／癒しの風／清水 |
| guard | 盾の受け止め／包む守り／石壁 |
| barrier | 薄明の結界／柔らかな結界／脈動する結界 |

## 重さの作り方

通常攻撃は、以前の短いノイズ・減衰する低音に、200〜1,000Hz付近の衝突音と倍音を持つ本体を加えた。重打は飽和させた下降音と長めの本体、一閃は風切りと鋭い共鳴、破裂は不規則な細かい砕け音を組み合わせる。破片や反射音は1回の命中の余波として扱い、戦闘のヒット数やダメージは変えない。

標準攻撃の素材ピークを0.53から0.70へ、範囲／破砕を最大0.74へ変更。回復0.48、結界0.54は穏やかにし、必殺技の主打撃0.83を下回る。音量の増加に加えて、重打・破砕は中低域の持続を増やしている。各素材の尺は520〜880msで、通常の最速行動950msの中に収める。

44.1kHzの素材の先頭200msを分析したRMSは、旧attackが0.096、一閃0.180、重打0.238、破裂0.238。150〜1,100Hzの無補正エネルギー割合は旧25.0%、一閃31.4%、重打67.1%、破裂41.7%。これは音の質や「体感の重さ」の点数ではない。スマホやBGMと合わせた試聴を行う。

## 再生と割り当て

同じキャラの攻撃で違いが巡るよう、AppからactorIdを渡し、キャラ×系統ごとに3種類を順に使う。他の敵や味方の行動でカウンターが進まない。試聴などactorIdのない呼び出しは独立した共通ストリームを使う。カウンターは64ストリーム以内、既存系統の波形は9系統×3種類、新規3系統を含む全キャッシュは36種類以内。ゲームの乱数・セーブ・戦闘計算には干渉しない。

旧PCMのhealパッチは比較用に残るが、heal／regen／mend_pair／barrier_mend／cleanseの実再生には使用しない。paralysisは新しい雷音、その他の対象外の補助・状態異常などは従来のToneレシピを使う。必殺技のパッチ・演出は維持し、通常スキルのtemplateより優先する。

native AudioBufferによる即時再生、共通SE音量、リミッターと過大ピークの保護を継続。連続発音は6本を基本上限に、未開始の古い音は即時取消、再生中の古い音は短く減衰する。BGM設定に触れない。

## 比較と検証

`npm run preview:combat-audio` は `artifacts/combat-audio/` に各系統の3種類を全て書き出す。`attack-1.wav` などの単体音、0.35秒の無音を挟む `attack-comparison.wav`、一覧の `index.html` を生成する。互換用の `attack.wav` などはバリエーション1と同じ。前回のように試聴が1種類だけになることを避ける。

自動検査は、サンプルレートごとの有限性・ピーク階層・端点、重打と一閃の帯域および持続の違い、材質の切り替わり、キャラ別の独立カウンター、キャッシュ再利用、連打上限、出力ピーク・ミュートと配布用iframeを対象とする。波形が違うことだけで聴感の品質を保証せず、人間の視聴確認は引き続き必要。
