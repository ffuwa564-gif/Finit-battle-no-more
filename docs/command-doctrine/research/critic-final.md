# 指揮動画・統合草稿 最終厳格査読

対象：`/workspace/stillveil-command-lab/scripts/command-lab/{chapters,cases,model}.py` と `artifacts/command-lab/delivery/Model-Results.json`。固定ゲーム版 `616a0747c4118a991770226d37347f34b31e2ec6`。ゲームと台本は編集せず、関数を読み取り実行して検算した。14章を通読。

## 結論

**企画研究動画として成立。実ゲームで低レア軍が逆転できることを実証した動画ではない。** 台本はこの区別を繰り返し示し、狭い勝ち筋・SSR側にも指揮・既存の集中AI・高レア人格への決めつけ・育成の罰を自ら批判している。重大な算術誤りや、現行へ実装済みと誤認させる断言は見つからなかった。

修正推奨は、(1) 同意対照の計算をコードから再現可能にする、(2) 号令自身の通常25充填を一度認める、(3) 通常攻撃も対象か一言明示、の三点。低レア逆転の主例は、未検証の「意図競合」を前提にした存在証明であり、有用性の証拠へ格上げしない。

## 1. 優先修正：全員C対照が関数から再現できない

`model.py allocate` は指揮なしなら常に `damage['A'] += 20`。従って `allocate(40,1,False,('C','C','C'))` の結果は A20/C120、SSRなら A20/C165。

一方、JSON `boundary.fullAgreementNoCommand` は R140/SSR185。`cases.py limits` は「本人の二十も加わる。低レア百四十、高レア百八十五をシーへ向けられる仮条件ね」と発話する。**本人もCを攻撃するという別仮定なら足し算は正しいが、その仮定が計算関数へ存在せず、出力は定数である。**

推奨：関数に `commander_target='A'` を与え、対照では `'C'` として実計算する。JSONへ本人の対象も保存し、C140/185、指揮あり120/165、差20をassert。あるいは対照の説明を本人Aへ統一すればC120/165で号令損失はC以外の20となるが、台詞の分かりやすさでは前者がよい。

固定されたA/B/C意図を持つ基本4条件は関数とJSONが一致する。これは基本の120対110を崩す誤りではない。

## 2. 算術の独立検算

|条件|A|B|C|合計予定火力|実変更人数|
|---|---:|---:|---:|---:|---:|
|R 指揮なし|60|40|40|140|0|
|SSR 指揮なし|75|55|55|185|0|
|R 指揮あり|0|0|120|120|2|
|SSR 指揮あり|0|55|110|165|1|

Rは三人を予約するが、Cを本来狙う三人目は変更していない。この人数を3変更/3服従ボーナスと呼んでいない点は適切。

- 敵CがHP115で全味方の後に動くならRだけが行動前に倒せる。
- R120とSSR110についてRだけ届く整数HPは111〜120の10個。
- SSR一手60なら二人で120、80なら160。
- SSR二人だけ独立50%変更ならC予定火力55/110/165の確率は25%/50%/25%。HP115へ届く確率25%。全三人の変更が必要な別条件の12.5%とは区別されている。
- sweepは41種のSSR値×180種HP＝7380行。

HPを超す予定火力を実HPダメージと呼ばず、対象死亡後の再配分もモデル範囲外と明示している。C撃破と全戦闘勝利を混同していない。

## 3. 号令は通常25充填を一度得る方が妥当

現行 `engine.ts:703` は、非必殺かつ状態異常による強制行動でなければ通常一手に25を付与する。号令は新しい通常一手として設計しているので、**発令時に通常25を一度得て、元の手番では再加算しない**のを第一試作とする。

現案はすでに、既存LSの席、本人の一手、対象が外れる可能性、通常AIでは十分な場面での無価値、を払っている。25まで失わせるのは、研究で必要性を示していない追加罰。危険なら後で比較するべきで、保守的に費用を積んでから「使えない」と判定してはいけない。

`cases.py contract` の「普通のゲージ充填を重ねたりもしない」は一回目の有無が曖昧。修正文例：

> 号令の一手にも、通常の二十五充填は一度だけ与える。元の手番で動いたり、二重に増やしたりはしないわ。

これは味方への追加ゲージ配布ではなく指揮官本人の通常行動分である。必殺予約との併用不可は維持。

## 4. 対象契約に小さい曖昧さが残る

`contract` は「敵単体技能だけ」と記すが、模型は全員を同じ一手の攻撃として表している。通常攻撃を含むのか、技能だけかを明示するべき。第一巡の設計趣旨では含む。推奨表記は「通常攻撃を含む、敵単体の通常行動」。回復/味方支援/全体/必殺/異常による強制行動を除外する点は保持。

入力時に受領者を予約しても、本人が手番で回復を選べば宛先変更は発生しない。使う技能の資格は既存の判定に従う。現在のAIの対象好みと合法な宛先を同一視せず、強化のない敵へ解除を向ける等の間違いも残す台本は適切。

全般的な挑発は現行にない。台本が追加済みの挑発や空間範囲を持ち出していない点もよい。かばうの受け手変更、睡眠を起こす危険、対象死亡後の通常判断復帰は具体的に述べられている。

## 5. 研究としてまだ証明していないこと

この逆転は、R低費用/SSR高費用、A/B/Cの意図競合、全味方が敵より先、HP115という組合せで作ったもの。台本は正直にそう述べているが、**「この新設計が現行の周回を面白くする」ことは一切まだ分からない。**

同じ通常攻撃なら現行BALANCEDはそろいやすいため、模型の三方向を自然に生む技能構成を次に最低一つ示す必要がある。解除・弱体・攻撃なら意図を分けやすいが、三つとも同じ40/55のダメージとはならず、解除対象変更が損になり得る。そこまで含めて有益な接続になるかが核心。

よって「強い軍を破れることが分かった」ではなく、現台詞どおり「逆転が生まれる仕組みの、一つの説明」に留める。CのHPを常にこの10の窓へ合わせる調整は、研究結果を敵へ仕込む行為である。敵のHP分布に対する割合や発生頻度はこの模型から出せない。

## 6. レア罰・育成・固定編成の評価

高レアの費用が高い理由を「自律的な完成度」と語るだけでは、費用差の妥当性は証明されない。台本が仮置き/未採用と示すのは必須。指揮適性を希少度とは独立にして覚醒でも保持する案は、育成罰を避ける方向としてよい。

ただし実際の育成でこの版の全キャラのレアリティが必ず上がる、と言ってはいけない。`agency` の「上位の姿にしたら指揮枠が増えて」は新設計の危険を問う仮定として読む。誤認をさらに減らすなら「もし覚醒後の希少度で費用を計算するなら」とする。

R1×3の三人が最適化で固定されたら低レアの種類は救われない。混成契約の石一枠も費用が実際に重いか未検証。SSR3→2とR1の混成を算術だけで完成形と扱わない現台詞は適切。単体ボスで指揮の価値が薄いことを認め、使わない判断を残す点もよい。

指揮官LSの席まで払う設計は自動的に正しいわけではない。第一試作で費用を一段ずつ比較すること。UI権限を一人のキャラに独占させて面白さを閉じ込める危険は、利用率と入力負担だけでなく「指揮官以外の編成でも標的選択が十分楽しいか」で評価したい。

## 7. 実装前の未決処理（動画の阻害要因ではない）

- 指揮官の状態異常を開始時だけ検査する簡略案と、元の速度手番の状態異常処理は同じではない。開始後に付いた睡眠/魅了等をいつ1ターン減らすか、元手番で二度判定しない状態表が要る。
- 指揮官＝手動先頭の時は、号令と個別操作/必殺を同じ一手へ同時予約させない。別キャラの手動操作が軍令より優先する規則とは別問題。
- 号令を通常25充填とするなら、ゲージ上限と次Rの必殺予約を通常どおり処理する。同一Rの追加手番に変換しない。
- 残響/連鎖は元行動の宛先と別。初期案で追撃の対象まで変えたことにしない。

以上を未決のまま「実装すぐ可能」とは言えないが、動画は実装決定ではなく小さな試作を提案しているため、全例外を台詞へ増やす必要はない。
