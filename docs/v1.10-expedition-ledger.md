# 周回実績の記録と読み方

`src/domain/expedition-ledger.ts` は探索の終了操作に合わせ、最新30件を端末内に保存する。外部への計測送信は行わない。

## 記録するもの

- 探索ID・ダンジョンID・版、踏破/全滅/期限/撤退、終了時に確定した経過時間、戦闘の観測要約、収穫、消費薬。
- claim/leaveFailureが成功してbattleを閉じた後だけ記録する。同一探索IDは既存記録を保ち、二度増やさない。
- 更新前に始まりtrackingを持たない探索は遡及収録しない。終了原因や途中経過を推測して補わない。
- trackingがあっても時計が不明/逆行なら時間はnull。実際に観測できた報酬と薬は残せる。

報酬は撃破時点で確保したゴールドに、終了時の正の確定差分を加える。石は確保済みgemFindsの件数、素材/記憶の欠片/祈願石は終了操作で確定した正の差分を使う。敗北・撤退でも撃破ゴールドと確保済み石が残る。未確定素材を収穫に加えない。薬を架空のG価格へ換算しない。戦利品なしの試練へ収穫が付いた不正な記録は拒否する。

## 集計

ダンジョン・contentVersion・rulesVersionで絞ってから全試行数/各結果件数/成功率を求める。成功率には失敗・撤退も含める。保存上限30件の中の実績であり、全期間の記録や将来の確率ではない。

時間が不明の記録は平均時間と時給の計算に入れない。計測数と平均時間には0msの観測も含む。0msは時計の有限精度による値で収益速度を評価できないため、時給の分子と分母の両方から外す。例えば0msで100G、10秒で1Gの2件なら、計測数2・時給対象1、時給実績は360Gとなる。0msだけなら時給は表示しない。

summaryの`earned`は全収穫、`timedEarned`は時間あり全件、`rateEarned`は正の時間だけ。`perHour`は`rateEarned / rateDurationMs`から計算する。異なる母集団の分子・分母を混ぜない。薬使用が不明な時給対象があれば薬時給だけnullとし、他の既知の収穫速度を消さない。

## 確認

`tests/expedition-ledger.test.ts` 14件通過。確定差分/既確保報酬、3失敗区分、旧探索の非収録、不明時計、30件上限、二重記録、試練、不完全探索の拒否、未計測収穫・0msの混入防止、版フィルター、未知薬を確認する。時計注入・永続保存・戦闘要約の実処理は別担当のintegrationで検証する。

この記録は攻略の保証、プレイ継続時間の予測、全編成の性能評価には使わない。
