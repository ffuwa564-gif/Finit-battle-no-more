# 確認パネルのseed変換（確認戦闘を実行する前の固定）

初期の粗探索/選抜には、910001〜/920001〜という隣り合う整数をアプリ出発前seedとして用いた。LCGの隣接入力は独立な乱数標本とは限らないため、そこで得た勝率を一般的なプレイ確率の推定や確認検定として扱わない。候補探索のパネルとして履歴に残す。

確認用930001〜930256、ストレス用950001〜950256、隠し戦場用960001〜960256は、**戦闘前に固定した行ID**とする。実際のアプリ出発前seedは、UTF-8文字列 `STILLVEIL:this-girl-01:uniform32:v1:<行ID>` のSHA-256の先頭4byteをlittle endian uint32として読む。`seed-bank.mts`を唯一の実装とし、最終lockにコードSHAと全対応表を収録する。行IDも実seedも、結果を見て選び直さない。

アプリのdepartは、この出発前seedへ既存のLCGを1回適用してbattle.seedを作る。両編成は同じ対応表を使い、Wave間の宝箱の抽選も既存のアプリと同順に進める。異なる行IDの32bit衝突、探索済みの出発前/戦闘初期seedとの衝突を確認し、もし衝突した場合は確認戦闘を開始せず記録してプロトコルを改訂する。条件間では同じ行IDを対応づける。

暗号学的ハッシュによる固定の疑似乱数パネルであり、全2^32状態の網羅や未来のプレイヤー行動の保証ではない。区間推定/検定のモデル仮定、有限パネルの限界、同seedで行動が分岐すると後続の乱数消費も分岐することを報告書に明示する。選抜と確認の分離を、公開コミットと最終lockのSHAで記録する。
