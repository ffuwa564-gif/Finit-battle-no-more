# 確認乱数を開かずに行う選抜

現行24戦場×T3/T4/T6×2制約（全員可/サクヤ必須）で、各64合法ビルド×同じ4探索seedを測った。これは探索であり実用性の認定ではない。双方の候補数・seed数は同じ。世界全体の厳密最適値を求めたものではない。

探索基準版を見て、次の6既存戦場で上位8候補ずつを同じ100選抜seedで再評価する。選定は改修前・確認用256seedを未使用の段階で固定した。塔1/5/10/15は現行の勝敗が分かれる層、通常終章two-signaturesと葛葉覚醒は勝率飽和時の効率も扱える異なるカテゴリ。通常の難度や敵は変更しない。24全体の到達不能/飽和も隠さない。

別の固定3人コア2組を、最良代替比較の入口として固定する。

- F1: athena / astraea / seris-awakened（高レア出力を持つ守りと攻撃）。
- F2: noelle-awakened / nox / seris-awakened（号令の機会費用を比較できる構成）。

同一familyは重ねず、差替え候補はヒーラーだけに制限しない。各側の石/リーダー/先頭/操作を同じ探索予算で調整する。サクヤLSとノエル号令の同時利用は不可。指揮した回数を、実際に対象が変わった回数と混同しない。

この段階の選抜を確認データとして使わない。確認前に最終能力・ビルド・比較仮説群を別のlockファイルへ保存する。未使用256seedの結果でステージや閾値を後から変更して合格にしない。

## 実アプリとの乱数同等性の修正（確認前）

最初の粗探索・選抜・全キャラscreenは戦闘エンジン直結で、Wave間のアプリ側宝箱抽選の乱数消費を省いていた。塔は最終Waveだけの抽選なので戦闘結果に影響しないが、通常/イベントの複数Waveは影響し得る。これらは探索候補の発見用に限定し、確認結果や収録再現の証拠に使わない。以後は既知の全石を発見済みとする最終盤条件で、`secureMemoryChest`と同じ条件・順序の抽選を通す。確認前に両版・全代替を同じアダプターで再選抜する。

F4: liora-awakened / astraea / seris-awakened（アテナを使わない守備コア）。F5: noelle-awakened / evelyn / seris-awakened（守護者を含む号令コア）。F1と同じ候補数/石/操作予算で、ヒーラー全17形態を比較する。初回F2/F3の不成立も履歴に保持する。号令は使用しない/複数敵時/使用可能時の3方針を候補に含め、指示回数と実際の宛先変更を別に数える。

実装候補の初回は障壁80%だったが、既存のイベント獲得回帰試験を壊した。敵や旧ヒーラーを変更せず、同じ既存試験の開発グリッドで90/100%も確認し、コストの残る90%を次の候補とした。確認データで80%を合格にしたものではない。新LS/新石は未採用。既存LSの機会費用と既存石の相乗効果を先に測る。
