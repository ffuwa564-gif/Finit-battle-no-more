# STILLVEIL 研究動画の完了条件

2026-11-04：ユーザーの「1パートで改修まで完成させる」という指示を反映。対象は「この子で、勝ちたい。」など、ゲームを良くする研究シリーズ。静かな独白、短い説明、本物の実戦、未達を認定しない方針は維持する。

## 動画化より先に終える工程

1. 対象の現状を実エンジンで測る。最初から不遇・失敗・成功と決めない。
2. 具体的な問題と、今回改善する範囲を定める。技能・LS・石・指揮の各案に採用/修正/見送り理由を付ける。4要素を一度に強化する義務はない。
3. 少なくとも一つの実際の能力・共通法則・判断ロジックを研究版へ改修する。数値表・台本だけの改修をゲーム改善と呼ばない。データ・共通処理によって実装し、対象専用の敵分岐や接待ステージを足さない。
4. 開発用/選抜用データで調整し、ソース・装備予算・操作・比較群・合格条件・未使用確認シードをGitへ固定する。
5. 改修前、改修後、必要な因果対照、同予算で再探索した最良既知代替を比較。確認は原則200シード以上、共通入力の対応比較。勝率だけでなく、ラウンド・薬・生還・固有貢献・石育成・機会費用を評価する。
6. 改善未達なら原因分析→設計→実装を繰り返す。確認データを調整に使った場合は開発済みと明記し、新しい確認シードを凍結する。都合のよい条件だけを残さない。
7. セーブ互換、乱数再現、既存戦闘、コンテンツ/型/UI/ローカライズ、他キャラへの影響を確認する。全キャラの外側最適化をしていなければ未検証のまま残す。
8. 採用する差分と、採用を支える改修前後の実測を確定してから最終台本・本収録・編集に進む。収録後は完成ファイルの映像/音声同期・デコード・実ブラウザ再生を検査する。

## 完了と認定を分ける

「一つの改善を実装・再検証し、明示した範囲で採用判断した」ことが1パートの研究完了。全キャラ・全石の大域最適や、最終盤での恒久的な採用価値の証明とは別。

全体の認定を義務にして、都合のよい実験や勝率だけで合格にしてはいけない。逆に全体認定が未達であることを、局所改修まで省略する理由にしない。未検証、不合格、改修採用、全体認定をそれぞれ記録する。

すでに十分な能力だった場合も、結果に沿って実際に改善すべき問題を再選定する。不要な強化を成功条件にしない。実害を示せる問題も有効な改修もない場合、障害を具体的に示してユーザーへ報告し、ゲーム改善回を完成と称しない。

## 必須の完了記録

回ごとの `episode-completion.json` に以下を残す。

- episode/revision、対象公開版/研究版、状態（development / blocked / implementation-complete / complete）
- 問題と採用した改修、ファイルとコミット、公開版には未導入かどうか
- 開発/選抜/確認データの分離、凍結コミットとSHA、比較群、事前合格条件
- 改修前後の実測生データと解析、因果対照、有限探索の範囲と不確実性
- 改善の採用理由、失敗案、未達項目、全体監査の実施範囲
- 回帰検証結果、実録映像、収録が実装済み研究版である根拠
- 完成動画のSHAとそのファイルに対する同期・デコード・視覚・ブラウザ検査

最終レンダラーはimplementation-completeの記録を検証してから書き出す。台本の断定に実測根拠を対応させる。「研究中」を免責文句にして、上記の工程を飛ばさない。

## 公開

研究版は専用ブランチで、公開版とセーブ/版/有効化条件を分離する。未公開能力には「研究版・未公開仕様」を表示。公開ゲームへのマージ/デプロイを、動画制作だけの依頼から推定しない。旧動画・旧ロックはそのまま保持し、改訂版を別のURLで公開する。
