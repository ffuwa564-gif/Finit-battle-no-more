# ビルド研究日誌 — みんなが輝くRPGを！

つむぎが「すべての少女に、その子がいてこその役目を見つける」研究を続けるシリーズの台帳。宝石が示すのは研究結果の状態であり、少女の価値や好き嫌いではない。

## 初回の登録範囲

- ソース：顔グラ修正後のゲーム1.11.0、main `489d5a4b15f02385c7229a2b2ff29f76da0abf44`。
- 公開75キャラの原画を確認した。少女のパレードは **72形態・明示的な同一人物リンクで49名**。
- 白霧の狼、石燐の幼竜、月翅の蛾の3体は少女の立ち絵パレードから外す。人型の「虚ろの守り手」は含める。
- 3クリーチャーはビルドの合法候補比較からは外さない。映像上の分類を、代替不能性の証明のための都合のよい候補制限へ使わない。
- 原画全体をcontain表示する。横長で膝上などの原画もあるため、存在しない全身を捏造したり、縦長へcoverして頭を切ったりしない。

## 永続ID

[serial-map.json](serial-map.json)に実装`characterId`ごとの`BD001`〜`BD072`を固定した。初回は公開コンテンツ順から3クリーチャーを除いた順。新登録は末尾へ追加し、削除・非公開化で欠番になっても再利用しない。並び替えや表示名変更で番号を振り直さない。

例：BD001エレイン、BD002リオラ、BD003セリス、BD004ノエル、BD069イオネ、BD070ネリ、BD071フィオ、BD072ルカ。

覚醒や衣装も別登録IDを持つ。認定の持ち主は、明示された`familyId`、覚醒リンク、イベントの通常／覚醒リンクだけから結んだ`canonicalGirlId`で追跡する。同じ少女の覚醒前後を「別の少女に役目を奪われた」と数えない。名前や絵が似ているだけでは同一人物にしない。

認定には`verifiedFormIds`を残す。同じ少女に宝石があることと、未検証の姿も同じ装備で勝ったことは別である。別の姿にだけ案がある登録は「案あり・別の姿」と注記する。

## 宝石と輝き

| 表示 | 状態 | 意味 |
|---|---|---|
| 宝石なし | これから研究 | この台帳にビルド案をまだ登録していない |
| 弱い輝き＋中抜き◇ | 案あり | ゲーム内の編成案や過去の研究がある。唯一解は未認定 |
| 琥珀の中抜き◇ | 試作・再検証中 | 研究案はあるが、最新条件の証拠待ち |
| 琥珀の塗り◆＋「試作」 | 試作認定 | 研究用ステージで必須性と勝利例を確認 |
| 水色の塗り💎 | 現行認定 | 現行ゲームの攻略先で必須性と勝利例を確認 |

初回は、現行の唯一解認定0名、研究用の「ほどける回廊」V4に対するルカの試作認定1名。新技・新石・試練は配信版には未実装。ゲーム内レシピの代替候補として載ることも「案あり」に含むが、特定キャラ必須の証拠へは読み替えない。

ノエルの号令、アメノウズメの巻戻し、フィオの白花は研究・実戦の履歴がある。ただし、その少女だけが突破できる攻略先の証明は登録されていないため、塗り宝石を遡って付けない。

## 次の研究ごとに行う審査

1. 新キャラ・新技・新石の追加前に、旧認定の全攻略先と、認定したときの条件・予算・候補・ルールを保存する。
2. 追加後の条件で、各攻略先の必須性を再審査し、代替攻略を試す。有限回の0勝だけで「他では不可能」とは証明しない。
3. 同じ条件を守った別の少女の勝利例が1つでもあれば、その攻略先の独占認定を外す。
4. ほかに再確認済みの専用攻略先が残れば宝石を維持する。登録した全攻略先が代替されたら塗り宝石を剥奪する。
5. 条件が変わったのに未検証、証拠不足、同じ少女の別形態の勝利などは保留。自動的に旧認定を継続したり、別人に奪われたと断定したりしない。
6. 現行版と研究版の認定は別。研究用試練が残っていても、それを理由に現行認定を維持しない。

キャラ能力・技・石・敵・ラウンド規則などのハッシュを、顔グラやBGMのハッシュと分けて追跡する。見た目だけの修正は戦闘上の条件変更にしない。現行コンテンツの実装IDは書き換えない。

台詞の基準：

> 宝石がないのは、あなたが弱いからじゃない。うちがまだ、その子のための勝ち筋を見つけきれていないだけ。
>
> 取り消すのは、その子の価値じゃなくて、うちの認定だよ。

## 初回に扱う撤回の正確な意味

ルカの現行第20／30層は、最初の比較では候補に見えた。しかし、覚醒エレインなどの実勝利が見つかり、仮説を棄却した。これは中抜き◇の候補を取り下げる履歴であり、正式な💎が後の新研究に奪われた実例ではない。

[gem-audit.json](gem-audit.json)はこの区別と反例を保持する。「正式認定がない」状態を都合よく演出上の「剥奪」にしない。

## 使用するファイル

- [registry.json](registry.json)：パレード、ID、原画、表情ではなく原画のハッシュ、フォーム、宝石表示。
- [gem-audit.json](gem-audit.json)：研究の条件と認定の根拠、候補の撤回、次回の審査規則。
- [girl-eligibility.json](girl-eligibility.json)：75キャラ全員の分類理由と確認した原画のハッシュ。
- [serial-map.json](serial-map.json)：永続連番。
- `scripts/build-diary-01/registry.mts`：最新版のデータから再生成する。親の最新再検証が未完了なら、試作の塗り宝石を保留する。

```sh
node_modules/.bin/tsx scripts/build-diary-01/registry.mts
```

検証元は`artifacts/build-diary-01/research/episode-evidence.json`、`revalidation-necessity-certificate.json`、`revalidation-edge-checks.json`。いずれも最新版のソース・版と一致して成功している場合にのみ、ルカへ試作認定を付ける。証拠の生成コード4本のハッシュと、戦闘ソースが撮影元コミットと一致することも照合する。証拠ファイルが存在するだけでは合格にしない。

## 映像シリーズの型

主役は眼鏡と白衣の春日部つむぎ。ずんだもんと四国めたんが疑問と比較を手伝う。強さの順位ではなく、少女ごとの仕事を見つける研究日誌として続ける。

1. 会話の背景で、その時点の全少女の原画をID・宝石つきで流す。全員の頭までcontainし、各登録が完全に見える時間を3秒以上確保する。
2. 少女一覧の後に新シリーズのkawaii future bass OP。複数の枝分かれの先に光るビルドと、つむぎの研究を描く。初回は25.6秒だが次回へ尺を無条件に固定しない。
3. 一人を選び、既存の面白さ、代替候補、うまくいかなかった仮説、新しい仕事、勝利例と必須性、ほかの三枠の選択肢、旧認定の再審へ進む。勝利だけを認定の根拠にしない。
4. 最新版の顔グラを使って収録し、実装済みと未実装の試作を画面で分ける。実ログ可視化を配信版本体の録画と表示しない。

映像は1920×1080・30fps。つむぎを左、会話相手を右へ320×440の安全な枠に収め、字幕は下部2行。ピンク、クリーム、淡いミント、琥珀の研究ノートを基調に、会話に沿って表情と図を切り替える。全景の挿絵では左右の立ち絵を隠す。
