# STILLVEIL 攻略日記・動画制作テンプレート

ユーザー承認済みの **Part2改良版（可愛いピンク版）** を、今後の攻略・解説動画の標準にする。各回の内容・尺・ゲストは変更してよい。別の演出が明示された場合は、その依頼を優先する。

![承認済みの本編レイアウト](https://raw.githubusercontent.com/ffuwa564-gif/Finit-battle-no-more/588105cf95eb0619fc382e9a00d07fa314be6bba/Preview.jpg)

## 最初に使うファイル

- [episode-brief.md](episode-brief.md)：回ごとにコピーして企画・開始条件・キャラの選定理由を書く。
- [storyboard.csv](storyboard.csv)：セリフ、図、録画の参照位置、着弾などの反応目標を対応させる。
- [style.json](style.json)：色・座標・字幕・音量・安全域の基準値。
- [image-prompts.md](image-prompts.md)：同じ雰囲気の表情差分・挿絵を作るプロンプト。

`style.json`は設計の参照値。既存Part2レンダラーが自動で読み込む設定ファイルではない。実装へ反映した値と絵コンテを、各回の制作記録に残す。

## 構成と会話

標準の流れは **共通OP → 短い見せ場・問い → 今回の条件 → 相手と編成の作戦 → 準備 → 実戦・見せ場の再掲 → 結果と次の目標**。OPはユーザー指定版を冒頭に使い、版と長さを確認する。Part2の23秒を次回へ無条件に埋め込まない。

- 1本の問いを決める。例：「守りは厚いのに時間切れ。誰の役割を変える？」。
- ずんだもんは疑問・喜び・失敗、めたんは理由とツッコミ、つむぎは勢いと別の見方を担う。毎回同じ役割だけに固定せず、ゲストは企画に合わせる。
- 「このキャラが強い」で終わらず、他の候補と比べて今回ほしい仕事を説明する。
- 数値の読み上げを続けず、疑問→図→答え→小さな掛け合いで進める。ネタは実際の出来事から作る。
- 会話の区切りで表情・強調・図を切り替える。同じ長文一覧や停止したゲーム画面を説明中ずっと残さない。
- 説明が続く所に作戦会議や買い物などの挿絵を挟む。尺は必要な内容から決め、20分へ水増ししない。
- 通常の間は短く保つ。着弾や画面を読むための意図した間を残し、無言の区間は一覧で確認する。

## 見た目の基準（1920×1080）

| 要素 | Part2の承認済み基準 |
| --- | --- |
| 配色 | 薄いピンクの斜線背景、クリーム色の中央、濃いピンク／プラムの文字 |
| 中央パネル | x296・y73・幅1328・高さ850 |
| 実戦 | 左にゲーム x310・y66・486×864、右にその場の要点・図 |
| 説明 | 中央を広い編成図・比較図・挿絵へ切り替える |
| 実況キャラ | 左右320×440、x0／1600・y470、発話時だけ小さく上下する |
| 字幕 | 48px・最大2行、話者別の暗い色＋薄い縁取り。下部のクリーム帯に配置 |
| 全景の挿絵 | 周辺の立ち絵を隠して重複を避け、全体をcontainで見せる |

ゲーム画面を装飾で隠さず、スマホでの視認性も確認する。図は敵の役割、かばう／全体攻撃、編成の仕事、必要素材、CD、実戦HP推移などから、各回に必要なものを選ぶ。

## 頭の見切れを防ぐ

- 生成段階で頭・耳・帽子・髪・靴の全体と周囲の余白を指定する。頭の欠けた原画は縮小しても直らないので作り直す。
- `cover`で切り抜かず、`contain`で配置。320×440の立ち絵枠は内側30px以上、標準32pxの余白を取る。
- 発話中の上下移動は最大3px。移動の両端でも頭・帽子・耳が画面と字幕に重ならないことを検査する。
- 生成原画、合成プレビュー、**配布する完成MP4**の開始・途中・終了と挿絵を目で確認する。アルファの境界検査だけで合格にしない。
- 話している人物と表示されるキャラ・表情を対応させ、字幕は2行以内にページ分けする。

## 事実と映像

ゲームのコミット／版、セーブの出所、比較用に整えた所持条件、装備・操作・確率要素を記録する。新しい回では対象バージョンを確認し、Part2の録画を新バージョンの実戦として流用しない。

勝利・ダメージ・素材数・HPグラフは実測ログから作る。複数条件を同時に変えた勝利を、一つのキャラの効果だけで説明しない。再掲・倍速・省略は画面に表示し、セリフと実際に起きたことを対応させる。外部の実況を参考にした場合、実視聴と公開情報だけの調査を区別し、見ていない映像の編集を分析したと言わない。

## 音と書き出し

1. 実ゲームSEを録画の映像と同じカットでトリム・速度変更する。必殺や妖精への反応は、実フレームの登場・着弾を基準に置く。
2. 長い録画は開始・中間・終了の複数点で映像と音の時計を測定。診断用の帯・音を公開版へ残さない。
3. 編集用カットは30fps／48kHz PCM、1フレーム1600サンプル。全音源を共通サンプル0へ一度に配置する。
4. VOICEVOXとBGM・実SEを一つのミックスにし、会話中はゲーム音を軽く下げる。最終中間音声は可逆FLAC、AAC変換は配布時の1回だけ。
5. 疎なPNGのconcatを複数同時に合成するとフレームの待ち行列が膨らむ場合がある。Part2では背景を30fps H.264、透過キャラを30fps QTRLEへ先に展開し、合成後に一時ファイルを削除して回避した。
6. キャッシュは入力・編集条件・処理コードのハッシュ一致で再利用。実行中にコードを変えて異なる処理の結果へ新しいハッシュを付けない。

## 公開前の検査と納品

- 完成MP4そのものの実ゲーム映像・SEと全話者を、元素材へ照合。主要戦闘の開始・中間・終了を網羅する。
- 映像は変化のある9枚連続フレーム（0.3秒）を照合し、似た静止フレームの誤一致を避ける。音の背景は元音源から独立に再構成する。対象を完成ミックスから引いて背景を作ると、欠けた音を検出できない場合がある。
- 許容ズレは80ms以内。相関不足・必要な検査点の不足も公開を止める理由になる。対象回に合わせて検査点を決め、Part2の時刻や18点だけをそのままコピーしない。
- 全体デコードと、Chromium／WebKit各3点の再生・シークを別に確認。頭の安全域・話者・字幕も検査する。
- 検査報告を完成ファイルSHA256へ紐づける。再書き出しした場合は再検査する。
- 動画、サムネ、プレビュー、字幕、台本、チャプター、YouTube説明文、クレジット、開始条件、元録画と制作ZIPへの参照、ハッシュ、検査JSONを保存する。
- VOICEVOX・キャラクター・楽曲・OPのクレジットを継承し、音楽や公式立ち絵を配布ZIPへ単体転載しない。公開ファイルを読み戻し、検査したものと同じハッシュか確認する。

共通の同期方針はルートAGENTS.mdと[media-sync.md](../../../media-sync.md)も参照。
