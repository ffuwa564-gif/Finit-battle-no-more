# 戦闘の着弾と数値更新

ダメージ数字だけ先に出て、HP・必殺ゲージは次のリプレイイベントへ進んでから変わっていた。通常行動では最大1.4秒、必殺技では着弾後も最大1.75秒ずれていた。

`CombatFeedback` の着弾コールバックで、数字の表示と `BattleView` の現在イベントの `unitsAfter` 表示を同時に更新する。通常行動は開始時、必殺技は既存の `ULTIMATE_TIMING.impact`（標準速度で1450ms）に揃える。HP・必殺ゲージの幅は同時に動き始め、120msで追いつく。数字は透明からのフェードインを待たずに出す。

差分の計算用に、直前のイベントまでを適用した `before` を保持する。表示用の更新済みユニットで差分を計算し直すと、速度変更時に数字が消えるため、両者を分ける。着弾判定はイベントIDに紐づけ、NEXT時には保留タイマーを破棄する。戦闘エンジン、保存済みHP、与ダメージ、獲得ゲージ量、演出全体の長さは変更しない。

撃破した敵は、その攻撃イベントの対象である間、空になったHPバーとともに表示を保つ。次のイベントで敵ページの自動切り替えを再開する。

`e2e/battle-impact-sync.spec.ts` は実エンジンから作った通常攻撃・回復・撃破・必殺技の結果を使い、次のイベントを待たずに数値が反映されること、溜め中の値は先取りしないこと、途中の速度変更とNEXTで値の巻き戻し・数字の重複が起きないことを確認する。
